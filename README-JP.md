# ZDPS モジュール最適化 — 今回の変更点（日本語）

このドキュメントは、**今回の変更分のみ**をまとめたものです。対象は「Module Optimizer（モジュール最適化）」まわりです。設定方法と、元の機能から変わった点を説明します。

---

## 変更点の概要

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 演算バックエンド | CPU のみ | **GPU(DirectCompute) / CPU（ビームサーチ・近似）をユーザーが選択**（既定 GPU）。自動フォールバックは行わず、失敗時は**エラーを表示して停止**。計算中は**進捗%を表示** |
| 総当たりの速度 | — | **列挙カーネルの刷新（オドメーター方式・バイト詰め）＋支配フィルタ（結果を変えない事前除外）**で大幅高速化（実測 約16億通り/秒: 196億通り≒12秒） |
| 計算結果キャッシュ | なし | **フル計算時に上位候補プールを保存**（10位スコアからXX%以内・既定20%）。インベントリが変わらない限り、再計算はプール再採点で**ほぼ即時** |
| スコアモード | ZScore（優先度重み）固定 | **ZScore / 戦闘力 の切替**に対応 |
| ZScore の計算要素 | 順位ブースト・レジェンダリ倍率・オーバーキャップ余剰点 | 順位ブースト・レジェンダリ倍率を移植。**改造版**ではオーバーキャップ余剰点を廃止し「20到達のステータス数を増やす」構成を優遇。**「計算方式」で「オリジナル」に切替**れば upstream 準拠の配点に戻せる |
| 探索対象 | ステータス優先度に一致するモジュールのみ | **総当たり（全モジュール対象）モードを追加**。優先度を設定しなくても全モジュールから最大 ZScore／戦闘力を探索可能 |
| 1セットのモジュール数 | 最大 4 | **最大 10** |
| UI 言語 | 英語のみ | **日本語に対応**（アプリの言語設定に追従） |

> [!NOTE]
> スコア計算式そのもの（戦闘力など）は元から実装済みのものを利用しています。今回はそれを「探索の最適化対象」として選べるようにし、GPU で高速に探索できるようにしたものです。

---

## 前提・動作環境

- GPU 演算は **DirectX 11 (Feature Level 11.0) 以上**の GPU で動作します（NVIDIA / AMD / Intel いずれも可）。
- 対応 GPU が無い・初期化に失敗した場合はエラーが表示されるので、設定タブで**演算バックエンドを CPU に切り替えて**使用してください（自動フォールバックはしません）。
- 追加のインストールやランタイムは不要です（既存の .NET 9 / DirectX のみ）。

## 設定方法

### 1. モジュール最適化ウィンドウを開く
ZDPS の「Features メニュー（右上の歯車アイコン）」から **モジュール最適化 / Module Optimizer** を開きます。

### 2.「設定」タブの新項目
ウィンドウ上部の **設定 / Settings** タブに、以下の項目が追加されています。

- **演算バックエンド（Compute Backend）**
  - **GPU（厳密・総当たり）/ CPU（ビームサーチ・近似）** をコンボボックスで選択できます（既定 GPU）。
  - GPU 選択時は、検出された GPU 名が下に表示されます。初期化に失敗している場合は赤字で表示されます。
  - **自動フォールバックは行いません。** 選択したバックエンドが失敗した場合は、結果欄にエラーと対処ヒント（対象モジュールを減らす／CPU に切り替える）が表示され、計算は停止します。

- **計算結果キャッシュ（Result Cache・GPUのみ）**
  - ON（既定）にすると、GPU フル計算のついでに「**10位のスコアから指定%以内（既定 20%）**」の組み合わせをすべてメモリに保存します。
  - **モジュールインベントリ（と対象モジュール・セット数）が変わらない限り**、次回以降の計算は総当たりせず、このプールを現在の設定で再採点して**ほぼ即時に**結果を出します。
    - 同一設定での再計算 → 即時（厳密）。
    - **必要リンク値（下限・マイナス指定の上限とも）だけ**を変えた場合 → プールから厳密に抽出（10件揃わない場合は自動でフル計算し直し）。
    - **スコア設定**（優先度の順序・スコアモード・計算方式・倍率等）を変えた場合 → プールを近似再採点し、結果欄に**近似の可能性**がある旨を表示します。厳密にしたい場合は「クリア」してから再計算してください。
  - インベントリ更新（テレポート/回線変更/リロード）で自動的に無効化されます。キャッシュはメモリのみで、アプリ再起動で消えます。
  - 設定行に現在のキャッシュ状態（件数・生成時刻・カット%）と「クリア」ボタンが表示されます。

- **スコアモード（Score Mode）**
  - 「**Zスコア (優先度)**」: 設定したステータス優先度・必要リンク値に基づく重み付けスコアを最大化します。
    - **必要リンク値（ReqLevel）が 0 の効果も通常の数値目標**です（要求による足切りが無いだけで、リンク値×優先順位の重みで採点されます）。優先度に追加した効果を含む構成が優先的に選ばれます。
  - 「**戦闘力**」: ゲーム内の戦闘力（戦力値）を最大化します。優先度は「最低リンク値の制約」として働きます。

- **計算方式（Scoring Method）**（Zスコアのみ）
  - Zスコアの配点を **「改造版」/「オリジナル」** で切り替えます（戦闘力モードには影響しません）。既定は **改造版**。
  - **改造版**: 21以上の超過分は加点しません（上限20・ブレイクポイントのみ）。
  - **オリジナル**: upstream準拠。到達ブレイクポイントを超えた分も加点します。
  - 総当たり・戦闘力モードはどちらの計算方式でも利用できます（配点方式とは独立）。

- **ステータスの上限・除外（要求リンク値にマイナス値）**
  - 各優先ステータスの **要求リンク値（R Lvl）欄にマイナス値**を入れると、そのステータスの**合計リンクの上限（cap）**として働きます（A/E 指定は無視され、A/E ボタンは無効化されて `<`／除外(-6)時は `×` 表示になります）。
    - `-1` = 16以下 / `-2` = 12以下 / `-3` = 8以下 / `-4` = 4以下 / `-5` = 1以下 / `-6` = **一切乗せない（除外）**
  - 上限を超える構成は候補から除外されます。**上限までは通常どおりスコアに加算**されるため、「このステータスは欲しいが特定ティアより上げたくない」という調整に使えます。
  - `-6`（除外）を指定すると、そのステータスを持つモジュール自体が計算対象から外れます（＝「入らないようにする」。「計算」ボタン横の組み合わせ数の目安にも反映されます）。
  - **GPU（厳密）**では上限を正確に適用します。**CPU（ビームサーチ・近似）**でも上限を尊重しますが近似のため、確実に反映したい場合は GPU を使用してください。
  - 上限（`-1`〜`-5`）も結果キャッシュのプール再利用の対象です（下限と同じ扱い。プール内で10件揃えば厳密・揃わなければ自動フル計算）。`-6`（除外）は候補モジュール集合が変わるため、除外の組み合わせごとに初回のみフル計算になり、以降はその候補セットのプールで応答します。

- **優先度ブースト強度 / レジェンダリ倍率**（Zスコアのみ）
  - **優先度ブースト強度**: 上位の優先度をどれだけ強く重み付けするかを調整します。重みは `1/(順位+1)^強度` で減衰します（0 = 全優先度が同等、大きいほど上位が支配的。既定 1.0）。
  - **レジェンダリ倍率**: レジェンダリステータスに適用するスコア倍率です（既定 2.0）。
  - 戦闘力モードでは無効化されます（実ゲーム値に忠実なため重み付けしません）。

- **1セットのモジュール数（Num Modules in a Set）**
  - スライダーで **1〜10** の範囲で設定できます（従来は最大 4）。

- **この合計値以下のモジュールを除外**
  - モジュール1個の**合計リンク値**（各ステータスのリンク値の合計）が、指定値**以下**のモジュールを計算対象から除外します。既定 **0（＝除外なし）**。
  - 弱いモジュールを外して探索対象（N）を減らせるので、総当たり時の計算も軽くなり、GPU 厳密計算で完了しやすくなります。

- **総当たり（Brute Force / 全モジュール対象）**
  - チェックを入れると、**ステータス優先度を設定しなくても**、所持している全モジュール（有効な品質）を対象に総当たりします。
  - **OFF 時は「優先ステータスを持つモジュール」だけが対象**（N が小さく高速）。**ON にすると対象が所持全モジュールに広がり、組み合わせ数が桁違いに増えて数分かかることがあります。**「計算」ボタン横に、現在の設定での組み合わせ数の目安が表示されます（GPU 選択時）。詳細は後述「B3」の補足を参照。
  - 並べ替え・最適化の対象は上の **スコアモード**（Zスコア／戦闘力）で選びます。結果には各構成の **戦闘力** と **Zスコア** が併記されるので、最大戦闘力を見たい場合はスコアモードを「戦闘力」にして再計算します。
  - 優先度を設定している場合でも総当たりは有効で、優先度は「必要リンク値などの絞り込み」として働きます（任意）。
  - 注意: 所持モジュールのステータス種類が多い（32種超）場合、GPU の厳密計算は使えずエラーになります。品質・カットオフで対象を絞るか、CPU バックエンドに切り替えてください。

### 3. 日本語表示にする
アプリの **言語設定を「日本語」**にすると、モジュール最適化ウィンドウのタブ・設定・結果・ツールチップなどが日本語で表示されます。

### 4. 計算を実行
「最適化 / Optimizer」タブで品質・ステータス優先度を設定し、下部の **「{N}個のモジュール構成を計算」** ボタンを押すと探索が始まります。計算中は**進捗%と経過時間**が表示され、キャンセルも可能です。結果には **戦闘力** と **Zスコア** が併記されます。

## 元の機能から変わった点（詳細）

### A. GPU 演算（DirectCompute）の追加
- 組み合わせ探索を GPU のコンピュートシェーダ（`Shaders/ModuleSolver.hlsl`）で**総当たり（厳密）**並列実行します。
- ZScore と戦闘力の両スコアに対応。
- **CPU 軽量モード（ビームサーチ・近似）**は設定タブの「演算バックエンド」で選択できます。スコア式は GPU と同一で、探索の網羅性のみが異なります。自動フォールバックはしません（失敗時はエラー表示で停止）。
- **CPU 軽量モードの精度改善（v0.1.7.3 追補）**: (1) ビーム枝刈りヒープの優先度キーが2種類混在し誤った候補を捨てていたバグを修正（結果が実行ごとに揺れる原因でもあった）、(2) ビーム内の**同一セット重複（順列違い）を排除**して実効ビーム幅を回復、(3) Exactly（ちょうど一致）指定へ両側から誘導する部分進捗を導入、(4) 探索後に**局所探索（1/2モジュール入替の山登り）**で仕上げ。実在庫387個での8ケース検証（Exactly複数・上限cap・除外・戦闘力/Zスコア混在）で、**全ケース GPU 厳密解と同スコアに一致**しました（原理上は依然近似です）。

### A2. 総当たりの高速化（結果は同一のまま）
- **列挙カーネルの刷新**: 従来は1組み合わせごとに「番号→モジュール組の復元（最悪 O(N) のテーブル参照）」を行っていましたが、各スレッドに連続区間を割り当てて「次の組み合わせへ1歩進める」方式（オドメーター）に変更し、先頭 K-1 個の部分和を使い回すようにしました。ステータス値のバイト詰め（uint に4値）も併用し、カーネル単体で数倍高速です（RTX 5080 実測 約16億通り/秒: 196億通り≒12秒、25億通り≒1.6秒）。
- **支配フィルタ**: 「別のモジュール K 個以上に全ステータスで劣る」モジュールを計算前に除外します。スコアがステータス合計に対して単調である限り**結果は完全に同一**です（単調性は実行時に検証し、「ちょうど一致」指定時やカスタム配点が非単調な場合は自動で無効化）。N が減ると組み合わせ数は冪で減るため、実質的な高速化はカーネル改善より大きいことがあります。**計算結果キャッシュが ON の場合（GPU・既定）は最初から適用しません**: 候補リストをゲート設定に依存させないことで、上限（cap）や「ちょうど一致」への変更でもプールを再利用できるようにするためです（フル計算がわずかに増える代わりに、以降の設定変更がほぼ即時になります）。
- **計算結果キャッシュ**: 上記「設定方法」の項を参照。フル計算は初回のみで、以降はインベントリが変わるまでプール再採点（数百ms程度）で応答します。
- **占有率と適応スライス（v0.1.7.3 追補）**: 1ディスパッチあたりのスレッド数を 16K→262K に引き上げ（GPU をほぼ遊ばせていた）、さらにスライスサイズを実測スループットから**約30msパケットに自動調整**するようにしました（TDR 限界の約60分の1を維持しつつ、ゲーム起動などで GPU が混むと自動で縮小）。実測: 696億通り 約27秒 → **約11秒**（RTX 5080）。
- 検証: ランダム生成した11ケース（ゲート/Exactly/戦闘力/K=1〜10/32stat/スライス分割/収集モード）で、GPU の結果が CPU の全数え上げ参照実装と**完全一致**することを確認済みです。加えて実在庫387個の8ケースで、GPU 厳密解を正解としたリグレッション検証（`--verify-solver` ハーネス、下記）を通しています。
- **Exactly（ちょうど一致）ゲートのバグ修正**: 複数のステータスに Exactly を指定した場合、従来は「**どれか1つ**が一致していれば通る」誤った判定で、2つ目以降の Exactly を破る構成が結果に混入していました。**全ての Exactly ステータスが合計値と厳密一致**する構成のみ通すよう修正（GPU シェーダ・キャッシュ再採点・CPU ビームの三者で同一判定）。
- **検証ハーネス**: `BPSR-ZDPS.exe --verify-solver <Dataフォルダの親> [--truth truth.json] [--mode both|cpu|gpu] [--repeat N] [--json out.json]` で、実在庫に対して GPU（厳密・キャッシュ無効）と CPU ビームを同一設定で実行し、スコア差・上位10件の一致率・時間を比較できます（GUI 起動なし）。`--truth` を付けると GPU 正解をファイルに保存し、以降は CPU だけを高速に再検証できます。

### B. スコアモードの切替（ZScore / 戦闘力）
- 従来は優先度重みの ZScore のみでしたが、**戦闘力（AutoMOD 方式に相当）**を直接最大化するモードを追加しました。
- 戦闘力モードは内部の `CalcCombosCombatScore`（ゲームのデータテーブル由来）に忠実です。CPU フォールバック時（ビームサーチ）も同じ戦闘力定義で探索します。

### B2. ヒューリスティック要素（ZScore）
- 以下の計算要素を、GPU 総当たり・CPU 軽量モードの両方に反映しています:
  - **順位ブースト（非線形）**: 優先度リストの上位ほど重み大（`1/(順位+1)^強度`）。
  - **レジェンダリ倍率**: レジェンダリステータス 8 種を既定 2 倍で評価。
- **オーバーキャップ余剰点は廃止しました。** 各ステータスの効果はゲーム内でブレイクポイント（1/4/8/12/16/**20** が上限）刻みであり、20 を超える分（21以上）は実効が増えません。そのため ZScore では **ブレイクポイントのみで評価（上限20・超過分は加点なし）** とし、1ステータスに盛るより「20到達のステータス数を増やす」構成を高評価にしました（例: `30,30` より `20,20,16` を優先）。
  - この変更は ZScore 全体（優先度モード・総当たりモード両方）に適用されます。戦闘力モードの式（`CalcCombosCombatScore`）は実ゲーム値のため変更していません。

### B3. 総当たり（全モジュール対象）モードの追加
- **ステータス優先度を設定しなくても**、所持している全モジュール（有効な品質）を対象に、最大 ZScore／最大戦闘力の構成を探索できるモードを追加しました（設定タブのチェックボックス）。
- 従来は「優先度に一致するモジュールのみ」を対象にしていたため、優先度が空だと結果が出ませんでしたが、総当たりモードではその制約を外します。
- 最適化・並べ替えの対象は **スコアモード**（ZScore／戦闘力）で選択します。各構成の戦闘力と ZScore は結果に併記されます。

> [!IMPORTANT]
> **「総当たり」という語は UI 内の2か所で使われ、意味（探索の規模）が異なります。**
> - **演算バックエンドの「GPU（厳密・総当たり）」**: 候補集合を*漏れなく全数評価*する、という意味です（近似のビームサーチに対する「厳密」）。評価対象はあくまで「候補集合」であって、必ずしも全所持モジュールではありません。
> - **チェックボックスの「総当たり（全モジュール対象）」**: 候補集合*そのもの*を、所持している全モジュールに広げる設定です。
>
> **通常（チェック OFF）** の候補は「優先ステータスを1つ以上持つモジュール」だけなので N が小さく、5枠でも一瞬で終わります（従来どおりの体感）。**チェックを ON にすると** 候補が全所持モジュールになり、組み合わせ数 C(N, セット数) が桁違い（数億〜数千億通り）に増えて、探索に数分かかることがあります — これは*本当の全数探索*であり、仕様どおりの挙動です。
>
> 目安として、**現在の設定での総当たり組み合わせ数は「計算」ボタンの横に表示**されます（GPU バックエンド選択時。候補モジュールから算出した上限値で、内部の重複・支配除外前）。重い場合は、品質の絞り込みや「合計リンク値カットオフ」で N を減らすか、優先度を設定してチェックを OFF にしてください。

### B4. 必要リンク値 0 の効果は通常の数値目標（存在タイブレーク方式は廃止）
- 一時期の版では「ReqLevel=0 の効果は数値目標から外し、存在のみを下位タイブレークとして扱う」方式（存在優先）を採用していましたが、**その効果を含む構成がほとんど結果に出なくなる**問題があったため**廃止しました**。
- 現在は upstream と同様、**ReqLevel の値に関わらず優先度に追加した効果はすべて数値目標**です（ReqLevel は足切りにのみ使用）。優先順位の重み（順位ブースト）が掛かるため、優先度に入れた効果を含む構成が優先的に選ばれます。

### B5. 計算方式の切替（改造版 / オリジナル）
- **B2（オーバーキャップ廃止）が「改造版」の挙動**です。設定タブの **「計算方式」** で **「オリジナル」** に切り替えると、upstream 準拠（超過分も加点）に戻せます。
- 既定は **改造版**。この切替は **Zスコアのみ**に作用し、GPU・CPU 軽量モードの両方で同一に動作します。戦闘力モードには影響しません。総当たりモードはどちらの計算方式でも利用できます。

### C. モジュール数 最大 10
- データモデル・CPU ソルバー・GPU カーネル・UI スライダーをすべて最大 10 に対応させました。

### D. UI の日本語化
- 文字列を既存のローカライズ機構（`AppStrings`）に載せ替え、英語（ベース）＋日本語を用意しました。
- 言語設定に追従して切り替わります。

### E. スライダーのホバー塗りつぶしバグ修正
- 「1セットのモジュール数」スライダーにカーソルを合わせると全体が塗りつぶされてスライダーが見えなくなる不具合を、ハイライト色を通常背景色に合わせることで修正しました。

### F. 内部バグ修正
- 5モジュール探索の合算ミス（`FiveModulesLoop`）を修正しました。
- **優先度設定時に結果が1件しか表示されない問題を修正しました。** CPU 軽量モードの「似た構成をまとめる」判定が優先度ステータスだけを比較していたため、要求を満たした構成同士がすべて同一と見なされていました。現在は全ステータスで比較し、ステータス構成が完全に同じもの以外は別の結果として最大10件表示します（GPU 側も同一ステータス構成の重複を除外して最大10件）。

### G. 計算プログレスの%表示
- 計算中バナーに **進捗%** を表示するようにしました（GPU: 処理済み組み合わせ数ベース、CPU: 探索深さベース）。経過時間と併記され、キャンセルも従来どおり可能です。

## 注意点

- **GPU 計算は TDR 対策済みの分割実行**です。以前は巨大な単発ディスパッチがゲームと GPU を取り合って Windows の 2 秒制限（TDR）に達し、画面がブラックアウト（ドライバリセット）することがありました。現在は約 400 万組み合わせずつの小さなディスパッチに分割・逐次フラッシュするため、この問題は発生しません。キャンセルボタンも GPU 計算中に即座に効き、そこまでの部分結果が表示されます。
- **設定（スコアモード等）は通常アプリ終了時に保存**されますが、異常終了で失われないよう、計算開始時にも自動保存するようにしました。また、プリセット共有コードを「適用」した後に変更した設定が保存されないバグを修正しました。
- **GPU が使えない・失敗した場合は自動フォールバックせず**、結果欄にエラーと対処ヒントを表示して停止します。設定タブで演算バックエンドを CPU に切り替えるか、対象モジュールを絞って再実行してください（ログに `GPU module solver initialized on adapter: <GPU名>` などが出ます）。
- **CPU バックエンドは近似探索**（ビームサーチ＋局所探索）です。GPU と同じスコア式を使い、実在庫での8ケース検証では GPU 厳密解と全て一致しましたが、原理上は最上位の組を取りこぼす可能性がゼロではありません。
- **総当たりで在庫が多い**場合でも、カーネル刷新＋占有率改善＋適応スライス＋支配フィルタにより、数百億通り規模で十秒前後が目安です（GPU性能に依存。RTX 5080 実測: 696億通り≒11秒）。計算中は進捗%が表示され、いつでもキャンセルできます（そこまでの部分結果を表示）。さらに短くしたい場合は、品質チェックや「合計リンク値カットオフ」で対象モジュールを絞る（＝ N を小さくする）か、CPU バックエンド（計算時間が組み合わせ数にほぼ依存しない近似）を使用してください。重複モジュール（同一ステータス構成）と支配されたモジュールは自動で除外されます。キャッシュONなら、フル計算は初回とインベントリ更新後のみです（キャッシュ生成のためフル計算自体は約2倍の時間になります）。
- 旧来の**自動 CPU フォールバック条件（組み合わせ数バジェット・GPU失敗時の自動ビームサーチ）は、DEBUG ビルドの Debug タブ内の設定**として残してあります（リリース版には存在しません）。

## リリース版への上書き反映

ビルドと配布物の組み立ては `update_package.bat` で行えます。

1. `update_package.bat` を実行すると、Release の単一ファイル exe を発行し、`ZDPS_UpdatePackage`（`BPSR-ZDPS.exe` ＋ ローカライズ用 `AppStrings.en.json` / `AppStrings.ja.json` / `AppStrings.ext.en.json` / `AppStrings.ext.ja.json`）と `ZDPS_UpdatePackage.zip` を生成します。
2. インストール済みのリリースフォルダに、生成された `ZDPS_UpdatePackage` の中身（または zip を解凍したもの）を**上書きコピー**します。
3. 日本語表示にする場合は、アプリの言語設定を「日本語」にしてください。

> [!NOTE]
> 今回の変更はすべて `BPSR-ZDPS.exe` と `AppStrings.*.json` に含まれます。その他の Data（画像・音声等）の追加配布は不要です。
